Create an implementation plan for the requested Crave change. Do not modify
source code.

Follow `crave-muse-protocol` STEPs 1–3 (UNDERSTAND → SELECT SKILLS → PLAN):
inspect the relevant source, architecture, components, backend contracts, and
tests; state which `crave-*` skills apply and why.

Return: objective · current implementation (with file refs) · proposed change ·
affected files · dependencies · backend impact · security implications ·
performance implications · accessibility implications · tests to add or update ·
validation strategy · risks and rollback considerations.

Ask for approval before implementing if the change is architectural,
security-sensitive, payment-related, or touches the backend contract.
